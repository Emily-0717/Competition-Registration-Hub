# 创新点与竞赛演示

## 项目价值

把分散在通知、文件夹和聊天中的报名工作，转为结构化要求、材料证据、版本指针和可重跑的提交核验。核心流程离线运行，适合学生团队准备报名与答辩。

## 三项技术亮点

1. **可解释规则核验**：逐条给出目标、级别、原因和自动 / 人工边界。文件扩展名、大小、哈希等机器证据与签章、原创性等人工事项明确区分。修复后可重新执行并保存历史报告。
2. **材料全程追溯**：每次导入都有不可变文件副本、SHA-256、修改人、说明和时间。当前版、审核状态、最终版分别管理，恢复不会破坏历史。
3. **可解释准备度**：展示材料、审核、资格和最终版的加权贡献，并通过临近截止或明确资格失败限制分数。展示原因而非单一黑盒评分。

## 建议 6 分钟演示

|时间|操作|展示证据|
|---|---|---|
|0:00–0:45|空库创建竞赛、赛道|首页统计随真实保存变化；材料模板待编辑|
|0:45–1:30|录入资格条件与材料规则|待确认条件和必填要求清晰可见|
|1:30–2:30|从选择器导入两个不同版本|独立副本、文件元信息、修改人和 SHA-256|
|2:30–3:15|指定最终版后恢复旧当前版|历史仍在，当前版与最终版相互独立|
|3:15–4:15|先执行失败核验，再修复大小 / 缺件 / 审核|同一规则可重复执行，原因可解释|
|4:15–5:00|展示准备度和风险|权重及截止原因，缺规则不虚高|
|5:00–5:45|导出 ZIP 并检查清单|最终版文件、TSV、报告真实存在|
|5:45–6:00|重启并查看记录|持久化（需提前完成真机验收）|

演示资料请使用自建测试竞赛和无隐私文件，明确为演示数据；不要声称应用已接入真实赛事官方报名系统。ZIP 导出是提交准备，实际上传提交仍由用户在官方系统完成。

## 评委提问边界

- 真实性、签章与报名资格由人工确认；本应用不代替赛事官方判断。
- SHA-256 用于检测副本变化，不等于法律意义的存证或可信时间戳。
- 准备度是透明的工程指标，尚无真实赛事样本验证其预测效果。
- 当前设备验证、后台定时提醒、拖拽、多窗口和内容差异均以测试报告为准，不能在答辩中宣称已完成。
