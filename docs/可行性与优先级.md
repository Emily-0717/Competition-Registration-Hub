# SDK 可行性与实施顺序

## 核实基础

以用户原工程 `build-profile.json5` 和本机 DevEco Studio 正式 SDK 为基准：6.0.2（22），Stage，`deviceTypes: ["2in1"]`。未声称支持所有更早的鸿蒙电脑系统。

2026 年 10 月查阅了[华为鸿蒙电脑适配指南](https://developer.huawei.com/consumer/cn/multidevice/pc/adapt)，并实际检查已安装 SDK 的 `.d.ts` / `.d.ets` 定义；官方网页存在动态渲染和抓取失败，因此接口签名主要以本机正式 SDK 及编译器结果核对。文档链接不代表已在设备上运行成功。

|能力|本地正式接口依据|实现决策与边界|
|---|---|---|
|关系数据库|`@kit.ArkData` → `relationalStore`|11 个表、父关系、索引、事务；无云端依赖|
|文件选择与另存|`@kit.CoreFileKit` → `picker.DocumentViewPicker`|使用授权 URI 打开描述符；复制到私有沙箱|
|文件 IO|`fileIo` / `fileUri`|显示元信息、存在性检测、备份及导出；不申请磁盘全量扫描|
|PDF 预览|`@kit.PDFKit` → `PdfView`、`pdfViewManager.PdfController.loadDocument`|实现应用内预览；设备系统能力和加密 PDF 错误待测|
|图片|ArkUI `Image`|常见图片格式应用内预览|
|DOCX / PPTX|UIAbilityContext.startAbility + viewData + MIME|交给已安装系统应用；无处理程序时显示错误；不伪造预览|
|哈希|`@kit.CryptoArchitectureKit` → SHA256|1 MB 缓冲块流式计算|
|ZIP|`@kit.BasicServicesKit` → `zlib.zipFile / unzipFile`|打包真实文件；恢复前检查 ZIP 中央目录|
|通知|`@kit.NotificationKit` → notificationManager|请求用户授权；应用运行时检查到期并通知；不实现后台唤醒|
|自由窗口|Stage 主窗口 + 响应式布局|宽窗口详情侧栏、窄窗口详情页；系统自由窗口由系统管理|
|多业务窗口|未启用|避免引入多窗口并发编辑与事务竞争，后续专项实现|
|文件拖拽|未启用|当前使用系统文件选择器，后续核对 UDMF 及 URI 授权生命周期再接入|

正式参考入口：[文件选择器](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-file-picker)、[关系数据库](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-data-relationalstore)。本机 SDK 相关定义：`@ohos.file.picker.d.ts`、`@ohos.data.relationalStore.d.ts`、`@ohos.file.fs.d.ts`、`@hms.officeservice.PdfView.d.ets`、`@ohos.zlib.d.ts`。

## 开发优先级及完成边界

1. 已实现：Stage 工程、十项导航、RDB、空状态与错误反馈。
2. 已实现：竞赛、赛道、资格、材料、团队成员和任务的真实保存；赛道材料模板。
3. 已实现：文件私有副本、SHA-256、独立历史、当前 / 最终指针。
4. 已实现：核验、可解释准备度、报告、最终版 ZIP 和备份恢复。
5. 已实现：浅深主题资源、列表 / 文件网格、任务月历、搜索排序、窄窗详情切换。
6. 待设备验收：文件授权、系统打开、PDF、RDB 持久化、ZIP 和通知。
7. 尚未实现：拖拽、多窗口、关闭应用后的定时通知、文件内容差异、可视化命名规则编辑器、规则文档解析。

当前交付是可继续设备验收的核心版本，不宣称已经覆盖需求文档全部增强能力。
