# 构建、签名与安装

## 环境

- DevEco Studio 6 系列，具备 HarmonyOS 6.0.2（API 22）正式 SDK。
- 兼容 API 22 的鸿蒙电脑 / 2in1 模拟器或真机。
- 测试签名所需的开发者账号、设备授权、证书和 Profile，由设备持有人配置。

工程只声明 `2in1`，没有以 Windows、Android、Electron 或 WebView 替代原生应用。首次打开工程时同步 Ohpm / Hvigor 依赖。`local.properties` 属于设备配置，由 IDE 生成，不随交付发布。

## DevEco Studio

1. Open 项目根目录，检查 product `default`、module `entry` 和 API 22。
2. 在工程签名配置中使用自己的账号开启自动调试签名，或选择合法的手动签名材料。包名为 `com.competitionhub.desktop`。
3. 选择连接设备，执行 IDE 构建和运行。调试时先验证新建竞赛与重启保留，再验证文件选择器。
4. 发布版本需要独立的发布证书和应用分发流程；本交付不包含发布签名或商店上架。

## 命令行

Windows PowerShell，在项目根目录运行：

```powershell
.\scripts\Build.ps1
```

DevEco 安装目录不同时传入 `-DevEco '实际安装目录'`。构建结果位于 `entry/build/default/outputs/default/`。未配置签名时得到 `entry-default-unsigned.hap`，不能当作已签名安装包使用。

签名后可用 SDK 自带的 hdc：

```text
hdc list targets
hdc -t <目标设备ID> install <已签名HAP的完整路径>
```

用户需启用设备开发者连接并信任本机。调试卸载可能删除应用沙箱，请先通过应用内完整备份保存资料。

## 本次执行环境的兼容处理

本次受限执行环境拒绝 Node 原生 realpath 和构建工具的部分链接 / worker 通信。构建时使用临时启动适配器：以标准 realpath 解析同一路径，把 Hvigor 模块解析指向本机已安装包，并直接执行 Hvigor 生成的官方 Java HAP 打包命令。

没有修改 HarmonyOS SDK 的接口定义、编译器、资源工具或应用源代码来掩盖错误。ArkTS 编译、资源处理、HAP 内容生成和 PackingCheck 使用正式 SDK。完整日志见 `evidence/build.txt`。常规 DevEco Studio 环境使用标准构建入口即可，不需要本次沙箱适配器。
